How implied value is computed

One function scores every row. No protocol name is special-cased, and no row is hand-picked. Growth and age are not fitted into the value: growth enters only as a bounded carry, a stated projection, and age enters only through the token odds.

if it launches = exp(6.9646 + 0.5223 x ln(TVL) + category_effect) growth carry = 1 + 0.01 x clip(change_7d, -25%, +25%) — a stated projection, not a fit token odds = logistic(0.1959 + 0.1682 x z(ln TVL) + 0.4281 x z(ln age, floored 365d) + category odds effect - 2.5 if a parent protocol already has a token), clipped 0.05–0.95 implied = if it launches x growth carry x token odds net on a ticket = implied x drop share x (ticket / TVL) - gas - ticket x 4% x (hold / 365)

Out-of-sample evidence

Each term is kept only if it lowers the held-out miss on both tests: leave-one-out on the 128 live-token protocols with a positive market cap, and walk-forward (older-listed protocols predict newer-listed ones). The flat median multiple is the baseline. Growth and age were tested in the value model and dropped — neither helped. The family effect lives in the odds, not the value: only 2 live comps are family children, so it cannot move the value fit.

Held-out validation

Fitted and tested on the 128 live-token protocols with a positive market cap. Leave-one-out miss ×3.39, walk-forward miss ×2.96 — against ×5.09 / ×5.33 for a flat median multiple. Token odds: in-sample Brier 0.209 against a 0.249 base rate, walk-forward 0.213. The board prints the middle-50% range (P25–P75, about 12× wide, 50.8% of live comps land inside it); the detail view also shows the wide P10–P90 range (about 123× wide, 79.7% inside). This model ranks, it does not price — implied values are order-of-magnitude scores with ~3.4× typical error, and the range on each row says so.
